# Phase 19 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Contract Intent

- Parity-first: web ingest, list, reader, and search must match mobile behavior semantics before introducing new features or visual drift.
- Deterministic failure handling: no silent failures. Every failure path must include explicit user-visible recovery actions.
- State continuity: returning from reader preserves list query, filters, and scroll position.
- Scope guardrail: no multi-select bulk actions, no list or reader keyboard shortcut packages, no fuzzy search, no persisted search history.
- Visual coherence guardrail: Phase 19 UI work MUST follow the already-migrated Mnemata design system in `CLAUDE.md`, `handoff/`, and `lib/core/theme/app_theme.dart`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label micro gaps, dense metadata separators |
| sm | 8px | Chip gaps, compact row spacing |
| md | 16px | Default screen padding and field spacing |
| lg | 24px | Section separation, modal body spacing |
| xl | 32px | Empty-state and reader block separation |
| 2xl | 48px | Major section breaks and dialog rhythm |
| 3xl | 64px | Large empty-state vertical spacing |

Exceptions:
- Minimum hit target is 44x44 for touch interactions on mobile web.
- Visual icon button sizes may appear as 32-40, but tap area must remain >= 44x44.
- Reader content column width is controlled by responsive layout, not spacing token scaling.

## Typography

Allowed typography in Phase 19 must come from `Theme.of(context).textTheme` and `textTheme.mono()` / `textTheme.tracked()` extensions.

Hierarchy contract:
- Serif (Instrument Serif): editorial headers and reader body.
- Sans (Geist): UI body, controls, labels.
- Mono (JetBrains Mono): tracked kickers and metadata (`source · read time`).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| UI Body (`bodyLarge`) | 15px | 400 | 1.5 |
| UI Label (`labelLarge`) | 14px | 500 | 1.4 |
| Editorial H3 (`headlineSmall`) | 20px | 400 (serif) | 1.25 |
| Editorial body (`titleLarge`) | 19px | 400 (serif) | 1.55 |

Do not hardcode font sizes in feature code unless explicitly required by design token exceptions.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `MnemataColors.paper` / `paperDark` (`ColorScheme.surface`) | App backgrounds, reader surface, form surfaces |
| Secondary (30%) | `paper2/paper3` (`surfaceContainer*`) | Cards, filter bar, optional reader side panel, grouped controls |
| Accent (10%) | `MnemataColors.accent` (`ColorScheme.primary`) | Primary CTA, selected chips, active search state, progress emphasis |
| Destructive | ColorScheme.error (material default red family) | Delete and other destructive confirmations only |

Accent reserved for:
- Primary Add Item CTA and Save action
- Active filter/search affordances
- Progress emphasis for ingest and heavy PDF loading
- Focus-visible outline for keyboard users on actionable controls

Accent must not be used for passive metadata text or decorative-only icons.

Hard rule for Phase 19 UI work:
- No `Colors.white/black/grey/red/...` in feature widgets.
- Use only `Theme.of(context).colorScheme.*` or `MnemataColors.*`.

## Copywriting Contract

Tone: concise, direct, parity-first, and action-oriented. Avoid vague language.

| Element | Copy |
|---------|------|
| Primary CTA | Add Item |
| Empty state heading | No items found |
| Empty state body | Add an item from URL or file, or clear filters and search to see all saved items. |
| Error state | We could not complete this action. Retry now, or return to list without losing your current filters. |
| Destructive confirmation | Delete Item: Move this item to the recycle bin? You can restore it later. |

Deterministic Phase 19 microcopy:
- Duplicate warning title: Duplicate Detected
- Duplicate warning body: This item is already in your list.
- Duplicate actions: Open Existing Item, Add Duplicate Item, Keep Current Item
- Oversize file error: File is too large. Maximum supported size is 25 MB.
- Unsupported file error: Unsupported file type. Phase 19 supports PDF and image files.
- Reader parse failure heading: Could not load readable content.
- Search inline error: Search failed. Retry, or return to list.

## Responsive Behavior

| Viewport | Contract |
|----------|----------|
| Mobile web (360-767px) | Single-column layout. Add flow opens as full-height sheet. Filter chips are horizontally scrollable. Reader side panel collapses into a secondary sheet action. |
| Medium web (768-1023px) | Single-column list with wider gutters. Add flow uses centered dialog up to 640px. Reader keeps one content column and exposes metadata panel as toggle. |
| Desktop web (>=1024px) | List remains single-column reading priority. Reader uses centered content column with selectable width and optional right metadata panel. Sticky header remains visible during scroll. |

Desktop reader layout contract:
- Content column max widths: 640, 720, 840 presets (user-selectable).
- Optional side panel width: 300-320.
- Sticky header height target: 56-64.

Global nav/header rules:
- AppBar stays transparent/flat per theme (no primary-colored app bars).
- Pushed screens must keep visible back affordance (do not rely only on iOS swipe gesture).

## Accessibility Constraints

- Text contrast must be at least 4.5:1 for body text and 3:1 for large text and icons.
- All icon-only controls require tooltip text and semantic labels.
- All interactive controls must be keyboard reachable in logical order (Tab then Shift+Tab reverse).
- Focus state must be visibly distinct from hover and selected state.
- Loading, success, and error feedback must be announced through semantic live regions where feasible.
- Do not rely on color alone for status; pair icon plus text for error and success states.
- Minimum text size in new Phase 19 web surfaces is 14px.
- Reader content must support text scaling controls without clipping actions or overlap.
- Returning from reader must restore list scroll, search query, and active filters exactly.

## Component Behavior and Interaction States

### Shared component usage contract (mandatory)

- Tags in list/filter surfaces: use `TagChip`.
- List rows: use `ItemCard`.
- Group headers: use `SectionLabel` from `lib/core/widgets/section_label.dart`.
- Reader bottom action cluster: use `ReaderActionPill`.

If an equivalent shared component exists, do not reimplement local variants in feature code.

### Bottom-sheet contract (mandatory)

- Top radius from theme (`MnemataRadii.xl`).
- Drag handle color `cs.outlineVariant`.
- Header with kicker via `textTheme.tracked(cs.secondary)` + serif title.
- Actions use themed `FilledButton` and `OutlinedButton` styles.

### WEB-01 Ingest (URL and file)

Components:
- One primary Add Item entry point.
- Unified Add panel with URL and File tabs.
- File tab supports file picker and drag-drop zone.

Validation contract:
- Allowed types in Phase 19: pdf, jpg, jpeg, png, webp.
- Maximum upload size in Phase 19: 25 MB.
- Validation runs before extraction.
- Invalid file type and oversize are blocking states with explicit inline error copy.

State sequence:
1. Idle
2. Validating
3. Duplicate check
4. Extracting
5. Summary edit (title, author, tags)
6. Save success and return to list

Deterministic failure states:
- Duplicate detected: modal with Open Existing Item, Add Duplicate Item, Keep Current Item.
- Extraction failure: guided fallback card with Retry Extraction, Open Original, Report Issue.
- Save failure: inline error plus Retry Save and Back to List options.

Post-save contract:
- Navigate to list.
- Show snackbar confirmation Item saved successfully.
- Keep summary visual pattern aligned with current ingestion screen style (tracked kicker + serif title + tokenized containers).

### WEB-02 List and filter parity

Components:
- `ItemListHeader` top row with monogram + icon actions.
- `LibraryTitleBlock` editorial headline beneath the top row.
- Horizontal `TagChip` filters with explicit More filters affordance.
- `ItemCard` row with quick actions: Open, Mark Read or Unread, Favorite, Delete, Share.
- `SectionLabel` date grouping for chronological sections.
- Infinite scroll pagination for long datasets.

State rules:
- Default order: newest-first, matching mobile semantics.
- Entering reader and returning must preserve list state exactly.
- Delete action requires modal confirmation and exposes snackbar Undo.
- Multi-select bulk actions remain out of scope for Phase 19.

Error and empty rules:
- Empty list uses No items found heading plus Add and Clear filters guidance.
- Stream/query error appears inline with Retry and Back to list actions.

### WEB-03 Reader and PDF parity

Components:
- Compact sticky header with Open Original, Share, and overflow actions.
- Desktop-centered reading column with optional side panel (metadata and TOC-ready slot).
- Reader controls: font size, column width, theme (light, sepia, dark).
- Embedded PDF viewer plus Open in new tab fallback.
- Floating `ReaderActionPill` pinned above safe area.

State rules:
- Reading position restore is approximate by section bucket.
- Heavy PDF loads display visible progress indicator.
- No keyboard shortcut package is introduced in this phase.

Deterministic failure rules:
- Parse or extraction failure shows guided error UI with Retry, Open Original, Report.
- URL launch failure shows non-silent snackbar error and keeps reader state intact.

### WEB-04 Search parity

Components:
- As-you-type query input with 300ms debounce.
- Contextual result list that respects active filters.
- Snippet preview with highlighted match terms.

State rules:
- Ranking semantics stay aligned with current mobile and FTS behavior.
- Search empty state includes clear next-step actions.
- Search history persistence and fuzzy matching remain out of scope.

Deterministic failure rules:
- Inline search error with Retry action and Return to list fallback.
- No raw exception dumps in final user-facing copy.

## Interaction State Matrix

| State | Visual pattern | Required actions | Determinism rule |
|-------|----------------|------------------|------------------|
| Loading | Inline spinner or progress bar with disabled conflicting actions | Stop Upload or Stop Extraction only if operation is explicitly cancelable | Loading copy stays stable for same operation type |
| Empty | Neutral icon + heading + short recovery text | Add Item, Clear filters, or Clear query | Empty messaging is contextual to list or search |
| Error | Inline error container with icon and text | Retry primary action plus safe fallback | Every error has at least 2 explicit next actions |
| Success | Snackbar confirmation | Dismiss or continue | Success message confirms completed action verb |
| Destructive confirm | Modal with clear consequence text | Delete Item and Keep Item | Action labels are explicit and outcome-specific |
