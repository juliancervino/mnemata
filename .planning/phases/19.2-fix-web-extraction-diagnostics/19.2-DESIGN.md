# Phase 19.2: Web Extraction Diagnostics and Refinement - Design

**Status:** Draft
**Date:** 2026-04-30
**Phase:** 19.2
**Requirement:** WEB-05

## 1. Problem Statement
Phase 19.1 attempted to fix web extraction using tiered proxies and JS-interop (Readability/Defuddle), but manual testing shows that URL and PDF extraction still fails on the web platform. The lack of detailed observability makes it difficult to distinguish between CORS blocks, proxy failures, or JS-interop processing errors.

## 2. Goals
- Implement detailed observability for the web extraction pipeline.
- Identify the root cause of URL extraction failures on web.
- Identify the root cause of PDF extraction failures on web.
- Refine the proxy pipeline to improve success rates.
- Ensure "Manual Ingest" is a reliable fallback when automation fails.

## 3. Architecture & Components

### 3.1. Observability Layer (New)
- **Extraction Logger:** A dedicated utility to capture the lifecycle of an extraction attempt.
- **Web Console Integration:** Detailed logs specifically for the web build, capturing:
    - Attempted URL and Proxy used.
    - HTTP status codes and headers (where available).
    - Latency per step.
    - JS-interop exceptions with stack traces.
- **Error Heuristics:** Map specific network/JS errors to user-friendly messages in the `IngestionFailureActionsSheet`.

### 3.2. Refined Extraction Pipeline (ExtractionService)
- **Proxy Tier 3:** Integrate `r.jina.ai` as a high-reliability fallback for sites that block standard CORS proxies.
- **Validation Step:** Add a "Pre-parse" validation to check if the HTML returned by a proxy is actual content or a "Challenge" page (Cloudflare, etc.).

### 3.3. PDF Web Refactoring (PdfExtractionService)
- **Byte Integrity Check:** Verify that the `Uint8List` passed to the service is valid and matches the original file hash.
- **Browser-Native Fallback:** If Syncfusion fails on web, explore using `window.print()` or a hidden iframe to extract text via browser primitives if possible (Spike).

## 4. Implementation Strategy

### 4.1. Step 1: Diagnostics (The "Lights On" phase)
- Instrument `ExtractionService` and `readability_platform_web.dart` with verbose logging.
- Add error boundary catching for all JS-interop calls.

### 4.2. Step 2: Analysis & Fixing
- Based on diagnostic data, fix the most frequent failures (e.g., incorrect proxy URL encoding, JS-interop type mismatches).

### 4.3. Step 3: Reliability & Fallback
- Add the Jina Reader fallback.
- Improve the transition to `ManualIngestDialog` when all automated tiers fail.

## 5. Success Criteria
- [ ] Every web extraction attempt produces a clear log trace in the console.
- [ ] At least 50% of the currently failing "Top 10" news sites work automatically on web.
- [ ] PDF extraction works on web for standard text-based PDFs.
- [ ] Manual Ingest is triggered correctly on 100% of unrecoverable automated failures.
