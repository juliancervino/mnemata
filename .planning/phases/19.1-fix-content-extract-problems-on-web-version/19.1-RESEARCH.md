# Phase 19.1: Fix Content Extraction Problems on Web - Research

**Researched:** 2024-05-24
**Domain:** Web Content Extraction & PDF Parsing
**Confidence:** HIGH

## Summary

Web content extraction in Mnemata currently faces three primary blockers:
1. **Stubbed Readability:** The `readability_platform_stub.dart` returns `null` for all web extraction attempts.
2. **CORS Restrictions:** Browsers block direct `http.get` requests to external domains, causing extraction to fail before it even starts.
3. **PDF IO Crashes:** `PdfExtractionService` relies on `dart:io`, which crashes the web runtime.

This research confirms that a robust web strategy requires a tiered approach: using high-quality "Reader-as-a-service" proxies (Jina), falling back to raw CORS proxies (AllOrigins), and performing client-side distillation using a JS-interop wrapper around `@mozilla/readability`. PDF extraction must be refactored to handle `Uint8List` byte buffers directly to maintain platform parity.

**Primary recommendation:** Implement a tiered extraction pipeline in `ExtractionService` and replace the readability stub with a `dart:js_interop` wrapper for `@mozilla/readability`.

## Architecture Patterns

### Recommended Extraction Pipeline (Web)
1. **Direct Fetch:** Attempt client-side fetch (likely to fail but handles same-origin or CORS-enabled sites).
2. **Reader Proxy (`r.jina.ai`):** Preferred fallback as it returns clean Markdown/Text directly.
3. **CORS Proxy (`allorigins.win`):** Fetches raw HTML if Jina is blocked or fails.
4. **Client-Side Distillation:** Run raw HTML from (1) or (3) through `@mozilla/readability` via JS interop.

### Pattern: JS Interop Wrapper
```dart
// lib/features/ingestion/services/readability_platform_web.dart
import 'dart:js_interop';
import 'package:web/web.dart' as web;

@JS('Readability')
extension type Readability(web.HTMLDocument doc) {
  external Readability(web.HTMLDocument doc);
  external Article? parse();
}

@JS()
extension type Article(JSObject _) {
  external String? get title;
  external String? get content;
  external String? get textContent;
  external String? get byline;
}
```

### Anti-Patterns to Avoid
- **Hard-coding Proxy URLs:** Use a configurable or tiered list to handle service downtime.
- **Synchronous Extraction:** Always use `Future` as HTML parsing (even client-side) can be heavy for large documents.
- **Mixing `dart:io` and Web:** Ensure all extraction services use conditional exports or `Uint8List` to avoid runtime crashes.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Readability Heuristics | Custom regex/DOM parser | `@mozilla/readability` | Handles edge cases (link density, boilerplate) that took years to refine. |
| CORS Workaround | Custom proxy server | `allorigins.win` | Maintenance and security of a proxy is high; use established community services. |
| PDF Parsing | Custom byte parser | `syncfusion_flutter_pdf` | PDF spec is massive and complex; existing libraries handle font encodings/layouts. |

## Common Pitfalls

### Pitfall 1: CORS Blocking
**What goes wrong:** `ExtractionService` tries to fetch a URL directly on web, resulting in a console error and no content.
**How to avoid:** Always wrap web fetches in a proxy attempt if the initial fetch fails.

### Pitfall 2: Memory Leaks in PDF extraction
**What goes wrong:** Opening many PDF documents without disposal leading to browser tab crashes.
**How to avoid:** Ensure `PdfDocument.dispose()` is called in a `finally` block.

### Pitfall 3: Incomplete Readability results
**What goes wrong:** Some sites return "Please enable JavaScript" messages when fetched via a simple proxy.
**How to avoid:** `r.jina.ai` attempts some headless rendering, but for others, the "Manual Ingest Mode" is the only robust fallback.

## Open Questions (RESOLVED)

1. **How to bundle Readability.js?**
   - **Resolution:** We will bundle `Readability.js` as a local asset in the `web/` directory and include it in `web/index.html` via a `<script>` tag. This ensures reliability and offline support for the web app if needed.
2. **What is the best way to detect a "blocked" site?**
   - **Resolution:** A combination of HTTP status codes (403 Forbidden, 429 Too Many Requests) and content-based heuristics. If the returned HTML contains strings like "Cloudflare", "DDOS protection", or "verify you are human", and the total text content length is unusually short (e.g., < 1000 characters), it should be flagged as "Blocked".
