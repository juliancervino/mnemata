# Phase 19.5: Improve mobile reading view - Context

**Gathered:** 2026-05-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Optimize the reading experience on mobile devices (Android/iOS) by improving content rendering accuracy and visual comfort, without modifying the underlying extraction engine.

</domain>

<decisions>
## Implementation Decisions

### Content Rendering
- **D-01: HTML Rendering Engine:** Switch the mobile reader to use `flutter_widget_from_html` (consistently with the web markdown reader). This is required to support structural elements like headings, bold, and italics that the current plain-text approach collapses.
- **D-02: Preserving Structure:** The implementation must explicitly preserve line breaks (`<br>`), carriage returns, and paragraph boundaries (`<p>`) found in the extracted content.
- **D-03: Styling Support:** Support standard rich text tags: `<strong>`, `<b>`, `<em>`, `<i>`, and `<h1>`-`<h6>`.

### Typography & Layout
- **D-04: Paragraph Spacing:** Apply a standard editorial gap of `1.5em` between paragraphs to improve legibility.
- **D-05: Responsive Margins:** Implement responsive horizontal margins (padding) optimized for mobile phone widths (target ~20px on standard phones) to ensure comfortable line lengths.

### Constraints
- **C-01: No Extraction Changes:** The extraction logic in `ExtractionService` or related processors must NOT be modified. Changes are strictly limited to the `ReaderScreen` and its rendering components.
- **C-02: Content Source:** Use the original `widget.item.content` for rendering instead of the destructively filtered `_plainContent`.

</decisions>
