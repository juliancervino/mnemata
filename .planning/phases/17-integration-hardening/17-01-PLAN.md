# 17-01-PLAN: Cloud Portability Integration and Safety Regression Suite

## Objective
Convert reliability assumptions into deterministic automated integration coverage, fulfilling the remaining testing requirements for Phase 17 (REL-01, REL-02, and REL-04). Existing tests already cover REL-03 (Scheduler) and REL-05 (Intelligence Fallback).

## Key Files & Context
- **`test/features/backup/cloud_to_restore_integration_test.dart` (New):** For end-to-end cloud backup and restore integration (REL-01).
- **`test/features/backup/backup_restore_service_test.dart`:** To add the missing required entries rejection test (REL-02).
- **`test/main_startup_test.dart` (New):** For verifying the startup ordering of ShareService vs BackupScheduler (REL-04).

## Implementation Steps

### 1. End-to-End Cloud Backup and Restore (REL-01)
- Create `test/features/backup/cloud_to_restore_integration_test.dart`.
- Write an integration test that wires together a mock `CloudBackupProvider` with the real `BackupArchiveService` and `BackupRestoreService`.
- The test must execute the complete happy-path flow:
  1. Trigger an archive creation.
  2. Upload the archive to the provider.
  3. List the available backups from the provider.
  4. Download the created backup byte payload.
  5. Stage the downloaded bytes as a temp archive.
  6. Successfully apply the staged restore without errors.

### 2. Restore Safety: Missing Entries Rejection (REL-02)
- Edit `test/features/backup/backup_restore_service_test.dart`.
- Add a new test case: `applyRestore aborts when archive is missing required entries`.
- The test will generate an archive that deliberately omits the `database.sqlite` entry but contains a valid manifest.
- Assert that `restoreService.applyRestore` returns an error of type `RestoreErrorCode.missingRequiredEntries`.
- Assert that the live database remains untouched (all-or-nothing guarantee).

### 3. Startup Ordering Verification (REL-04)
- Create `test/main_startup_test.dart`.
- Write a test to simulate the app bootstrap sequence (the initialization part of `lib/main.dart`).
- Assert that the synchronous registration of the `ShareService` listener happens *before* any background execution of the `BackupSchedulerService` (which uses `unawaited`). This guarantees the share intent receiver is non-regressed and non-blocking.

## Verification & Testing
- Run the full test suite via `flutter test`.
- All integration tests must pass deterministically.
- These automated tests serve as the final verification evidence for Phase 17.
