<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| settings UI to cloud provider APIs | Untrusted remote metadata and download failures cross into restore-selection UX. |
| downloaded archive bytes to restore pipeline | Cloud payload must remain untrusted until manifest and checksum validation completes. |
| backup result persistence to diagnostics UI | Incorrect status writes can mislead user about backup safety state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-16 | T | restore-from-cloud staging path | mitigate | Stage downloaded bytes in temp path and run existing required-entry plus checksum validation before apply. |
| T-11-17 | I | backup diagnostics display | mitigate | Persist explicit status fields (remote id/result code/timestamps) and render directly from SettingsService values. |
| T-11-18 | D | restore chooser flow | mitigate | Handle list/download failures with deterministic error paths and block restore sheet launch on failed download. |
</threat_model>
