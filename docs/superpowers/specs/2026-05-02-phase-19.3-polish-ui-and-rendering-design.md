# 2026-05-02-phase-19.3-polish-ui-and-rendering-design.md

## Goal
Polish the web reader experience by improving content rendering (specifically paragraph spacing), enabling tag management directly from the reader, and cleaning up unimplemented UI elements.

## Success Criteria
1. Articles render with clear paragraph separation (1.5em margin-bottom).
2. Users can add, remove, and create tags directly from the Reader view via a dialog.
3. The "Bookmark" action is removed from the reader's action bar.
4. Changes are strictly visual/presentational and do not affect extraction services.
5. Layout on web/desktop feels integrated and polished.

## Architecture & Components

### 1. Reader Rendering Enhancement (`lib/features/reader/presentation/reader_screen.dart`)
- **Markdown Processing:** Enhance `_convertMarkdownToHtml` to robustly handle paragraph breaks (`\n\n`) and block structure.
- **CSS Styling:** Update `HtmlWidget` custom styles to include explicit `margin-bottom` for `<p>` elements.
- **Content Fidelity:** Ensure the bridge between `plainContent` and `HtmlWidget` preserves original structural intent.

### 2. Tag Management in Reader (`lib/features/reader/presentation/reader_screen.dart`)
- **Action Pill:** Replace the placeholder "Bookmark" action with a "Tags" action.
- **Dialog Integration:** Invoke `LabelSelectorSheet` (or equivalent) to allow real-time tag updates.
- **Reactive UI:** Ensure the `_LabelsRow` widget in the reader correctly reflects database changes immediately.

### 3. UI Cleanup & Web Polish
- **Removals:** Strip out the `_togglePin` method and its associated button in `ReaderActionPill`.
- **Layout:** Refine `ReaderControlsBar` and `ReaderSidePanel` positioning on desktop to avoid awkward spacing or overlapping.

## Implementation Constraints
- **Isolation:** No changes to `lib/features/ingestion/services/extraction_service.dart` or related extraction logic.
- **Platform Safety:** Ensure changes to reader rendering are thoroughly tested on web but remain safe for mobile (maintaining parity where appropriate).

## Data Flow
- **Tags:** Reader View -> Label Service -> Database -> Reader View (via Stream).
- **Rendering:** Item Content -> Regex/Parser -> HTML -> Widget.

## Testing Strategy
- **Manual Verification:** Verify paragraph spacing with long-form articles.
- **Tag CRUD:** Verify adding/removing/creating tags from reader updates the database and UI.
- **Visual Audit:** Confirm the "Bookmark" icon is gone and the "Tags" icon works.
- **Regression:** Ensure mobile reader still functions correctly.
